# Every page names the module it starts with; the not-found page's is the app's :not-found-module

> The user's decision, 2026-10-26, from Iron Rainbow's port onto groundwork-3: groundwork-browser-build v0.5.0's [A page starts with a module](https://github.com/p4ulcristian/groundwork-browser-build/blob/v0.5.0/decisions/2026-10-26-a-page-starts-with-a-module.md) and [files-for-page is the one reader of the build's manifests](https://github.com/p4ulcristian/groundwork-browser-build/blob/v0.5.0/decisions/2026-10-26-files-for-page-is-the-one-reader-of-the-manifests.md), taken by groundwork v7.0.0. Changes in part [The routing extras, each where it belongs](2026-10-23-routing-extras-each-where-it-belongs.md): a page's `:module` was a module loaded on demand, and the shell listed `main`'s files only.

**Decision:** groundwork pins groundwork-browser-build v0.5.0: the page half (`groundwork-browser-build.page`, `:deps/root "page"`, malli only) in `:deps`, the whole library in the build aliases. The app map's `:browser-entry` is gone: the app's `:browser-modules` are the build's, all of them, one the root (`:depends-on #{}`, its `:start` what was the entry). Every page names the module it starts with, `:module`, a keyword of `:browser-modules`, required; the not-found page (a GET no route and no file answers) starts with the app map's `:not-found-module`, required. A page that names none, a string, a module the app doesn't have, or a `:not-found-module` it doesn't have, refuses the start (`:groundwork.server.main/bad-pages`), every problem at once. The page shell links the files browser-build's `files-for-page` reads for the page's module (its stylesheet bundle and its code, and those of every module it depends on, the root first), asked once per module at the start: while watching, after `start-watching!` returns, which wrote the manifests at its first compile; the `:module-stylesheets` the browser hands `load-module!` are browser-build's `stylesheets-for-load-module`. page.clj's own readers of the manifests are deleted. So groundwork is v7.0.0.

**Why:** a page should download what it shows at once, and only the page knows which app it is; a hidden fallback module would be a default, which groundwork has none of. The not-found page is drawn by an app's code like any page, and which module holds that code is the app's to say: the root alone may start nothing (Iron Rainbow's root, `:base`, has `:start nil`).

**Instead of:**
- **`:module` optional, a page with none starting with the root:** a default value nobody wrote, and a page that shows nothing when the root has no start
- **the not-found page starting with the root:** the same; or with the module of the address's nearest page: a guess
- **the module in `render-page`'s answer:** the shell's files would be chosen per request, and the page's module said in two places
