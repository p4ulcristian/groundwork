# The composer takes the switch's library releases

> Decided by the agent releasing the composer, 2026-10-27, from the user's brief (release the composer with the changes Iron Rainbow's switch needs; take the libraries it lags behind on). Since v8.0.0. Changes in part [The composer takes named refusals](2026-10-23-the-composer-takes-named-refusals.md) (one more reason of groundwork-access's) and [An app's own server routes are records with a kind](2026-10-23-an-apps-own-server-routes-are-records-with-a-kind.md) (the `:sign-in!` tool).

**Decision:** groundwork pins groundwork-access v0.8.3, groundwork-live-updates v0.6.2 and groundwork-file-storage v0.2.2 (it pinned v0.7.15, v0.5.14 and v0.2.0), and takes what they changed:

- **groundwork-access v0.8.** The `:access` settings are its new ones, `:outside-issuers` among them (`[]` for none). Its `outside-subjects-table` (`groundwork_access.outside_subjects`, which person each subject at an outside issuer is) is migrated, granted and checked with groundwork's tables, `[:silent "no screen shows which person an outside issuer's subject is"]`. Every `sign-in!` the composer makes writes out `:session-lasts` and `:outside-subjects`: the `:person` route's tool is `(sign-in! person-id {:session-flags #{} :session-lasts :session-days :outside-subjects {:workos subject}})`, in place of `(sign-in! person-id session-flags)`. Its new reason, `:groundwork-access/token-refused` (an outside issuer's token that failed its check), needs its text in every catalog (the start's `check-texts-of-reasons`, through `access/refusals`), and `:groundwork/browser-error` declares it beside `:groundwork-access/not-allowed`, on both sides, since its find-session step may give it. Where the composer runs the find-session step itself, the refusal is answered: [A refused outside token is answered 401](2026-10-27-a-refused-outside-token-is-answered-401.md). What the step found is read with `:token-id` and `:outside-issuer` (`asker/read-asker`: the `:person` route's `:asker`, `:may-upload?`'s). v0.8.3's `run-as-asker-of-request!` hands its `f` the asker: [A page's asker is found once](2026-10-27-a-pages-asker-is-found-once-in-its-one-transaction.md).
- **groundwork-live-updates v0.6.** The browser's question store is made with the page's document, `(make-question-store send! store-settings {:page js/document})`, so a page nobody sees asks nothing again until it is seen; `:live-updates :store` has `:ask-again-at-most-every-ms`, which the page carries. A write's good answer tells the store each table its notes name, `hear-own-changed-table!`, so the writer's screens ask again at once, past the window; groundwork-screens' own `hear-changed-table!` for the same tables, in the same gathering, changes nothing of that.
- **groundwork-file-storage v0.2.2** (v0.2.1 moved the bucket onto the AWS SDK for Java v2): the server test makes its bucket with `groundwork-file-storage.bucket/make-bucket!`, in place of the signing namespace v0.2.1 removed.

**Why:** the switch puts Iron Rainbow on these releases; the composer stood at the ones before them, so an app on groundwork could not take them.

**The price:** every app's `:access` and `:live-updates :store` settings gain a key, its catalogs a text, and its `sign-in!` calls two options.

**Instead of:**
- **the composer filling `:session-lasts :session-days` and `:outside-subjects {}` in the route's tool:** a default the app can't see; an impersonation's one hour would need a second tool
- **screens' write answers told as the writer's own change in groundwork-screens:** the composer's `send-write!` is where a write's answer arrives; screens is unchanged
